## 已实现

- SQLite只持久保存手动创建的档案、称呼和交流方式，提供增查改删。匿名会话及原v1/v2仍可使用；服务重启保留档案，内存会话重新创建。
- 切换/退出档案、修改/清空偏好、档案改名/删除：数据库提交成功后，取消相关在途请求、清空历史并推进epoch。写失败不改会话。模型每轮只读当前偏好JSON快照，避免旧称呼从历史重新进入提示。
- v1真实TCP断开后取消本请求拥有的轮次；v2保留既有断流取消、分句交付和双TTS。停止不要求模型计算500ms内结束，迟到结果不可交付。
- 模型退出、阶段超时挂起、RPC损坏均能标记worker不可用；后续轮次终止并重建该role，其他模型保留。首次失败仍显式返回，不伪造音频。
- 档案路径的成功响应和已处理HTTP错误带no-store；纯ASGI send包装保持语音receive通道原样。
- 启动数据库或ready元数据失败会清理自有常驻进程。显式`--profiles-db`支持跨output-dir的持久化路径，部署/回退准备见A运维说明。

接口与B调用顺序见`docs/development/profile-api.md`。档案不是账户认证；本次仅用合成档案和远端loopback 8004，不把个人数据放到公开入口。
