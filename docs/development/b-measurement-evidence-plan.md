# 09采集身份与条件核验

基线：B `83cf63936ab5f4c6cf24ba4195bfbaf3f48dfeff`。本轮是09的软件采集/计分增量，不是物理验收完成，也不解除11的前置依赖。

## 问题与结果

现有页面记录资产和WebGL renderer，但计分器未核对这些字段；physical-av甚至可不关联原始采集清单。因此仅有一组可配对标注不能证明素材属于当前头部和当前条件。

修复后，对包含冻结资产身份的任务，缺少身份、资产不一致或渲染条件不完整都成为整次采集失败，40事件仍在分母。外部物理素材同样关联其文件哈希、冻结表和采集清单。身份/条件不合格时不得显示eligible-for-human-evidence-review。即使全部软件核验通过，也只允许进入人工证据复核，不能自动批准物理验收。

不修改原冻结音频、40事件、95%/200ms规则、旧ledger或旧报告。无资产上下文的历史/合成ledger可保留诊断用途，不能成为物理验收捷径。元数据哈希只能保持字节可追溯，不证明声明的真实性。

## 操作入口

在现有measurement.html中，载入外部拍摄素材后，由操作者明确声明它对应当前页面条件；完整播放、可听声音分别声明。清单标记operator-declared，校准默认pending；audio_ms/visual_ms保持null直到独立标注。没有明确声明就不生成看似有效的物理清单。不通过生成浏览器闪光/声音来替代独立采集链路校准。

## 实施与验证

1. 在测量CLI公开入口先复现错资产/缺条件仍能得到分数，再增加核验与逐项失败原因。错误路径或哈希仍拒绝输入；有效但不合格采集保留0/40报告。
2. 在公开页面/媒体文件边界验证物理清单导出前置声明、原始媒体哈希和空白标注；使用明确合成素材，不伪称物理采集。
3. 跑measurement Python与受影响浏览器套件，串行使用默认实际renderer；记录原始红绿日志。代码/规格分别审阅后集中修复并提交B分支，不改A后端或main。
4. 若操作者提供真正同期屏幕/扬声器视频和独立校准素材，再根据真实条件开展标注与物理评分；否则交付可执行采集步骤并保持09 open。
