# 数字人优先的单卡离线情感交互与蒸馏规格

Type: spec
Category: enhancement
Status: ready-for-agent

版本：1.1。编制日期：2026年11月10日。最新范围调整：暂不实现机器人与数字人的映射控制，优先完成数字人。发布状态：已发布到项目本地 Markdown 跟踪器。分诊状态以顶部 Status 字段为准。

## Problem Statement

项目需要先建立可独立运行的情感交互数字人，为情感机器人方向提供后续研究基础。首期在实验室面向单人中文交互：听取用户发言、理解文本情绪、生成共情回复，并协调语音、可见三维头部表情和嘴部动作。

用户最新决定先做数字人，暂不做机器人与数字人映射控制。因此，原先含实体舵机、串口、标定与实机同步的范围不再作为首期交付或启动条件。软件仍从零开始；用户确认5090已到位，两名软件开发人员全职投入，现有目录只有汇报材料和其生成辅助文件，没有可复用的数字人程序或产品测试。

本规格把既有情感、语音、视觉、记忆和研究要求收敛到数字人首期，明确工程表现与蒸馏收益分别验证。原三份汇报文档及对应HTML反映包含实体映射的旧范围，不能在未改版时与本规格并列作为首期验收依据。

## Solution

交付完整离线运行的浏览器三维头部。用户手动选择档案并按轮次发言；ASR把语音转为文字，情感对话LLM输出用户文本情绪、回复和数字人表达意图，TTS生成语音。数字人根据回应意图、实际音频播放时间和人脸位置混合面部参数，在屏幕上呈现表情、嘴部开合与注视。

用户情绪与数字人表达意图区分处理。首期嘴部只要求围绕语音起止和停顿开合，不实现音素级唇形。摄像头仅做人脸检测与数字人注视；支持手动停止、异常提示和跨会话明确偏好的增删改查。数字人运行和验收无需实体机器人接入。

同一张5090分时承担学生训练和全部本地交互推理，优先采用千问系。仅训练情感对话LLM，语音及人脸检测集成现成模型。保留中文文本七分类的独立蒸馏研究：相对同一未经本项目适配的学生基座，错误率下降至少20%。研究未达标不阻止已经满足要求的数字人工程独立验收。

## User Stories

1. 作为实验用户，我希望在实验室中用中文与数字人交谈，以便验证面对面情感交互的完整体验。
2. 作为实验用户，我希望系统在已准备好本地资源后断网也能启动和交互，以便演示不依赖云端实时服务。
3. 作为实验用户，我希望语音被转为文字后进入对话，以便通过自然发言使用系统。
4. 作为实验用户，我希望看清监听、生成、播放和停止状态，以便知道何时开始下一轮发言。
5. 作为实验用户，我希望数字人能够承接本次会话的上下文，以便连续表达一件事情。
6. 作为研究人员，我希望系统区分高兴、悲伤、愤怒、恐惧、惊讶、厌恶、中性七类文本情绪，以便建立可复现的识别任务。
7. 作为实验用户，我希望数字人回应我表达的感受，以便获得与当前对话有关的共情回复。
8. 作为实验用户，我希望数字人根据回应意图选择表情和语气，以便得到适当的回应，而非被机械镜像情绪。
9. 作为实验用户，我希望回复能够通过清晰语音播放，以便不依赖阅读屏幕完成交互。
10. 作为实验用户，我希望声音、数字人表情和回复内容协调，以便理解数字人的表达意图。
11. 作为演示人员，我希望屏幕上能看到三维头部，以便观察对话对应的表情和嘴部动作。
12. 作为开发人员，我希望数字人的表情、嘴部与注视由明确的面部参数驱动，以便可重复地控制屏幕表现。
13. 作为实验用户，我希望数字人在说话时开合嘴部，以便声音和可见动作配合。
14. 作为实验用户，我希望嘴部在停顿和说话结束时闭合或回到已定义状态，以便避免声音结束后仍持续运动。
15. 作为演示人员，我希望使用具备所需面部参数的三维资产，以便表达首期对话所需的表情。
16. 作为实验用户，我希望摄像头能够检测我是否在场及脸的位置，以便触发基本的注视交互。
17. 作为实验用户，我希望数字人看向人脸位置，以便感受到正在与我交互。
18. 作为演示人员，我希望数字人首期不依赖ESP32或实体舵机在线，以便优先完成独立可运行的数字人。
19. 作为实验用户，我希望通过可见按钮停止当前回复，以便主动中断不想继续听的内容。
20. 作为实验用户，我希望停止后旧任务和排队动作不再恢复执行，以便安全地开始新一轮交互。
21. 作为操作人员，我希望模型、音频或数字人页面失败时看到明确状态，以便及时定位失败环节。
22. 作为操作人员，我希望页面恢复后不补播过期音频和动画，以便避免突然重放历史回应。
23. 作为实验用户，我希望手动创建和选择本地用户档案，以便明确当前偏好属于谁。
24. 作为实验用户，我希望系统记住我明确要求保留的称呼和交流偏好，以便在下一次会话中继续使用。
25. 作为实验用户，我希望查看已保存偏好，以便确认记忆内容是否正确。
26. 作为实验用户，我希望修改已保存偏好，以便后续回复使用更新后的内容。
27. 作为实验用户，我希望删除偏好后不再被后续回复引用，以便控制持久记忆的内容。
28. 作为实验用户，我希望切换档案时不引用其他人的偏好，以便各用户的记忆保持隔离。
29. 作为实验用户，我希望重启后仍能读取同一档案的有效偏好，以便验证跨会话保存确实生效。
30. 作为研究人员，我希望使用外部教师生成待审训练材料，以便在单卡条件下进行响应蒸馏。
31. 作为研究人员，我希望只训练情感对话 LLM，以便将有限人力集中在约定的研究任务上。
32. 作为研究人员，我希望教师样本经过标签与回复质量复核，以便减少合成错误对学生训练的影响。
33. 作为项目负责人，我希望所有教师调用累计不超过100元，以便控制研究开支。
34. 作为项目负责人，我希望模型、代码、数据、音色和数字人资产满足项目商业使用要求，以便后续使用有明确来源依据。
35. 作为研究人员，我希望优先使用授权明确的现有中文标注资源，以便减少重复标注工作。
36. 作为研究人员，我希望现有数据不适配时使用原创或明确授权的人工标注后备集，以便研究不依赖未经确认的数据来源。
37. 作为研究人员，我希望七类定义、样本量和标注规则在评测前冻结，以便对照结果使用一致的评价口径。
38. 作为研究人员，我希望训练集、开发集和最终留出集隔离并去重，以便避免评测数据泄漏。
39. 作为研究人员，我希望以同一未经本项目适配的学生基座作为对照，以便将变化归因于本项目训练。
40. 作为研究人员，我希望基线与蒸馏版本使用相同提示词和运行条件，以便公平比较错误率。
41. 作为研究人员，我希望蒸馏后相对错误率下降至少20%，以便证明约定分类任务上的研究收益。
42. 作为研究人员，我希望同时看到原始错误数、各类表现和混淆情况，以便判断总体成绩是否掩盖薄弱类别。
43. 作为研究人员，我希望追加实验依据开发集决定，以便最终留出集保持独立。
44. 作为研究人员，我希望保留模型、数据、配置及预测版本，以便重现成功或失败的结果。
45. 作为开发人员，我希望学生训练能在单张5090上完成，以便遵守既定算力条件。
46. 作为开发人员，我希望语音、对话、视觉与三维数字人运行在同一台单卡主机上，以便完成整套离线交互。
47. 作为开发人员，我希望训练和交互有明确的显卡使用窗口，以便避免共享资源挤占联合调试。
48. 作为数字人开发人员，我希望先验证三维资产的面部形变参数和使用许可，以便明确首期能展示的表情范围。
49. 作为数字人开发人员，我希望回应意图能映射到有效面部参数，以便避免无效权重或参数冲突破坏动画。
50. 作为数字人开发人员，我希望语音与面部动画共享实际播放时间基准，以便减少可见嘴部与声音的漂移。
51. 作为验收人员，我希望用可验证的屏幕呈现和实际音频采集测量同步，以便不把内部参数时间一致当成可见效果达标。
52. 作为验收人员，我希望固定事件中的缺失、无法配对和超限动作也计失败，以便同步成功率不漏掉失败样本。
53. 作为验收人员，我希望系统连续运行至少30分钟并完成至少20轮交互，以便验证约定的工程稳定性。
54. 作为验收人员，我希望至少95%的固定嘴部起止与停顿事件相对音频偏差不超过200毫秒，以便量化同步效果。
55. 作为验收人员，我希望按钮触发后500毫秒内停播并取消待执行的数字人动作，以便验证完整的停止路径。
56. 作为项目负责人，我希望单列三秒响应优化结果，以便了解体验进展而不改变首次工程验收门槛。
57. 作为项目负责人，我希望先看到语音到可见数字人回应的贯通演示，以便及早检查首期关键链路。
58. 作为项目负责人，我希望按数字人首期重新估算两人全职工作量，以便不沿用包含机器人联调的旧周期承诺。
59. 作为项目负责人，我希望研究首轮约4至6周、未达预期时最多追加两轮，以便限制探索投入并保留评审点。
60. 作为项目负责人，我希望研究用尽预算或轮次后提交真实结论，以便决定是否另行批准后续工作。
61. 作为项目负责人，我希望工程与研究分别验收，以便已满足工程标准时不被研究不确定性无限推迟。
62. 作为项目负责人，我希望规格明确标出数字人优先的阶段调整及旧汇报材料的适用范围，以便使用一致的实施依据。
63. 作为项目负责人，我希望实体映射与控制留待后续独立评估，以便首期工作集中在数字人。
64. 作为项目负责人，我希望报告区分已确认需求、待核实接口、候选方案与实测结果，以便不将规划误认为系统已完成。

## Implementation Decisions

### 首期模块与责任

- 首期交付对象为可见的浏览器三维头部及其本地情感交互服务。暂停数字人到机器人映射、串口或USB控制、舵机标定和实体联调；不为这些后续工作预建适配器或占位模块。
- 待建模块包括交互编排、ASR、情感对话、TTS、浏览器三维面部、人脸检测、本地档案与偏好、离线训练评测。当前没有现成产品接口、测试或ADR可以直接复用。
- 开发者A负责模型、语音、对话、档案偏好存储、训练评测和教师费用台账；开发者B负责三维资产接入、浏览器界面、数字人注视、动画与音频同步。两人共同负责接口、集成及验收。
- 采用单人中文轮次交互，用户说完后数字人回应，不实现语音抢话或持续边听边说。保留本次会话上下文；长期偏好由独立档案存储提供。

### 单卡环境与模型候选

- 使用可运行原生Linux的单5090主机，训练与完整交互分时运行；本地准备模型、依赖和资产后，断网也能启动和交互。教师API只用于离线数据准备。
- 学生首选验证Qwen3.5-4B，资源不满足时验证2B后备；ASR优先验证Qwen3-ASR-0.6B；情感语音优先验证Qwen3-TTS-12Hz-1.7B-CustomVoice。模型、框架、精度和量化设置均需许可、兼容性与整机实测确认，不将候选写成已验证方案。
- 只训练情感对话LLM。采用教师API离线生成待审材料、学生监督微调的响应蒸馏；LoRA优先，QLoRA作为资源与兼容性验证后的选项。不要求教师与学生同卡在线计算logits。
- 记录驱动、CUDA、模型与框架版本、上下文和启动参数。整套推理包含语音、视觉和三维渲染，不能只用LLM权重可加载证明单卡运行达标。

### 情绪语义与可取消任务

- 七类用户文本情绪固定为高兴、悲伤、愤怒、恐惧、惊讶、厌恶、中性。文本分类不代表用户完整心理状态，也不自动对应七种数字人表情。
- 对话结果分别携带用户情绪、回复文本和数字人表达意图。表达意图依据回应需要选择，例如理解悲伤后温和关怀，而非机械复制用户情绪。
- 校验模型输出的必需字段、长度和枚举；无效输出有限重试或进入明确的中性回退，记录失败。
- 每次发言有唯一标识，停止或重置推进会话代次。生成、合成、音频和面部动画可按同一发言取消；迟到的旧代次结果不得重新播放。

### 三维面部与音频同步

- 使用许可满足项目商业用途、具备所需面部形变参数的三维头部资产。先验证实际可用参数，再定义表达意图到表情的映射；不承诺未经资产验证的表情能力。
- 表情、嘴部与注视在数字人面部控制层混合，形成最终参数帧。参数包含发言标识、会话代次、帧序号、音频相对时间和归一化权重，用于驱动浏览器呈现与重放分析。
- 实际音频播放位置是同步主时钟。嘴部先按音频节奏、起止和停顿开合，避免音频结束后持续运动；此能力不称为音素级唇形。
- 人脸检测优先采用轻量CPU方案，只提供在场信息和位置，驱动数字人看向人脸。不增加面部情绪、人眼视线估计、场景问答或身份识别。
- 本期参数契约只服务数字人控制、同步和可观察性，不据此承诺实体兼容或安排舵机控制工作。

### 停止和异常恢复

- 手动停止独立于模型生成执行。从界面收到按钮事件起，500毫秒内停止实际音频，并取消或失效化尚未执行的数字人动作。
- 停止须覆盖服务端待交付任务、音频缓冲和浏览器动画队列。不能只清空后端列表而继续播放前端缓存；也不要求GPU计算本身必须在500毫秒内完全终止，过期结果不得再生效。
- 模型超时、音频失败或数字人页面失联时给出明确状态，不继续消费过期输出。恢复后确认当前会话代次，不补播失联期间的音频或动画。

### 档案与跨会话偏好

- 用户通过界面手动创建或选择本地档案，不使用人脸或声纹确定身份。
- 本地持久保存称呼及用户明确要求记住的交流偏好，提供新增、查看、修改、删除。SQLite为当前技术方案的存储默认选择。
- 仅将当前所选档案的有效字段注入对话。更新和删除同时使相关缓存及后续提示失效，不把偏好写入模型权重；重启后仍应保持有效状态和档案隔离。
- 不默认永久保存全部聊天、推断人格或建立持续关系状态。运行日志不自动汇入训练，保留必要的档案操作与失败记录。

### 数据和蒸馏评测

- 研究与交付均使用满足项目商业用途许可的模型、代码、数据、音色和三维资产，分别记录来源、版本及限制。正式数据源尚未冻结，不将明确非商业数据列为已承诺来源。
- 优先核查现有中文人工标注数据的许可和七类适配；不能满足时，启用已经确认的原创或明确授权文本后备方案，独立人工标注与复核。样本量、类别覆盖、标注和失败规则在评测前冻结，不看预测结果剔除难例。
- 教师输出是待审训练材料，不能作为测试金标的唯一裁判。训练、开发及最终留出集隔离并去重，最终测试内容不得进入教师示例或训练选择。
- 基线为同一未经本项目适配的学生底座；与蒸馏版使用相同提示词、上下文规则、标签、解码和运行条件。关闭记忆或固定同一档案快照，避免个性化信息污染对照。
- 主指标为相对错误率下降至少20%，计算为“基线错误率减蒸馏错误率，再除以基线错误率”。它不是准确率相对增长20%或提高20个百分点。
- 同时报原始错误数、错误率、各类样本量与表现、宏平均F1、混淆矩阵和解析失败。基线错误率为零时比值未定义，不自动判为达标。
- 迭代与候选选择依据开发集；最终候选冻结后统一终评，最终留出结果不用于选择提示、参数或追加方案。保留原始失败，不改换测试集使结果好看。
- 七分类收益不自动证明共情回复或动画表现改善；回应内容与声音表情的协调另作功能检查和人工审阅。

### 预算和阶段安排

- 教师API累计上限100元，包含所有轮次的生成、重试和教师评审；记录用量与费用，预算不足前停止新请求。不承诺固定样本数，不以未核实单价或免费额度作为预算依据。
- 两人全职，每周按5个工作日规划。首阶段先核验离线模型、三维资产和浏览器音频基线；随后贯通对话与动画，补齐记忆、注视和异常恢复，最后按数字人工程指标验收。
- 原8至12自然周、80至120人日和第3至4周实体完整演示，均是包含机器人映射联调的旧范围估算，不作为数字人首期承诺。数字人工程周期在首阶段基线后重估，不能凭减少硬件工作直接宣称固定缩短幅度。
- 保留研究首轮约4至6周、最多两轮追加各约1至2周的初步研究工作量安排，与数字人工程交错使用人员和单卡；这不是数字人工程交付日期。迭代上限和教师累计100元不变，用尽后提交结论，由负责人决定是否另行批准后续工作。

## Testing Decisions

### 按数字人优先调整的测试边界

工程以数字人交互入口为主边界，覆盖启动、选择档案、输入发言、停止、查看状态和重启；研究以独立离线评测入口为边界，覆盖固定数据与模型输入、预测明细和指标输出。此前涉及实体机器人的测试边界被本次范围调整取代，不新增串口替身、控制板或舵机测试入口。

当前没有可沿用的产品测试或接口先例。现有汇报文件的生成校验只证明文档内容与版式，不是数字人运行证据。自动化测试可在同一数字人入口替换模型、音频输入和摄像头，控制时钟验证外部行为；最终还需连接真实模型、音频和浏览器完成离线验收。替身不证明5090性能或可见渲染同步达标。

### 好测试的标准

- 验证用户可见回复、持久记忆、实际音频和屏幕数字人行为，不绑定内部类、私有状态或调用次数。
- 固定输入、预期结果、模型软件版本、资产参数、时间基准及全部失败，保存可重复执行的证据。
- 同步以可验证的屏幕呈现和实际音频采集为准，不能只比较内部计划时间或参数帧时间。共情适当性和表达协调允许人工审阅，不能以演示印象代替计时和研究对照。

### 数字人工程验收

既定工程指标保留，观测对象改为可见数字人，实体测量和设备队列要求移出首期。

| 测试 | 外部行为和通过口径 |
| --- | --- |
| 完整闭环 | 中文语音经ASR、情感对话、TTS到可见三维头部贯通，表情和声音符合回应意图 |
| 表达控制 | 表情、嘴部和注视参数实际改变浏览器中可见头部，声音与动画都关联当前发言 |
| 连续运行 | 完整数字人系统连续运行至少30分钟并完成至少20轮交互；一轮为用户输入至数字人回应结束，保留异常和重启记录 |
| 嘴部同步 | 固定测试中至少95%的预期嘴部起止及停顿事件，相对实际音频偏差不超过200毫秒；测量可见嘴部，不只比较内部权重 |
| 失败事件分母 | 全部冻结预期事件进入分母；缺失、无法配对、提前或滞后超限均失败，另列诊断信息 |
| 手动停止 | 从界面收到按钮事件起，500毫秒内实际停播且待执行数字人动作取消或失效；所有固定停止用例均需满足 |
| 迟到和恢复 | 停止后旧生成、合成、音频及动画不重新生效；页面恢复连接不补播历史任务 |
| 档案隔离 | 用户手动选择身份并看到当前档案，不同档案不串用偏好 |
| 记忆持久化 | 偏好增查改删和重启后状态一致；删除后不再经存储或缓存注入旧值 |
| 数字人注视 | 单个人脸在场及位置可供数字人注视使用，不测试实体眼球、头部或人眼视线估计 |
| 完整离线 | 预备本地模型、依赖和资产后，断网启动并完成交互，不调用实时云服务 |
| 异常状态 | 模型超时、音频失败、页面失联和档案修改失败可见；恢复不消费过期输出 |
| 响应优化 | 暖机固定短问句中至少95%在用户说完后3秒内开始有意义的语音；这是优化报告项，不是首次工程否决条件 |

测试前冻结固定输入、事件、计时与判定规则；声音和画面使用可关联时间基准。不得事后剔除失败事件，不用平均偏差替代95%比例，不用提示音或占位回应代替有意义的回复。

### 独立研究验收

- 同一未经项目适配的学生基座与蒸馏版，在相同提示、上下文、标签、解码和记忆条件下预测独立人工金标。
- 同一固定留出集上计算相对错误率下降是否至少20%。例如基线准确率80%、训练后84%，对应错误率20%降至16%，相对错误率下降20%；这仅解释公式，不是实测结果。
- 记录每类样本量、错误数、宏平均F1及混淆情况，无效分类输出计失败，不能只报告可能被中性类占比影响的总体成绩。
- 验证训练、开发与最终留出数据隔离；开发集决定迭代，最终候选冻结后统一终评，保留逐条预测。
- 基线零错误时报告比值不可判定；预算或轮次用尽而未达标时保留真实结论，不降低门槛、不换留出集、不用辅助改善代替主指标。
- 核对数据来源许可、人工复核、教师调用和累计费用记录，验证100元是所有轮次的总额。
