# Ticket 08 browser development baseline

Recorded 2026-11-14 on ticket/08-face-gaze after merging integration baseline `5ce3770`. At this historical development baseline, ticket 08 remained open for real live-camera evidence and integration review; see the later update below.

- Browser: Chrome 157.0.8103.51, Windows, headless SwiftShader WebGL 2. This is client-browser evidence, not 4090D/5090 inference acceptance.
- Real CPU inference: locally bundled MediaPipe Tasks Vision 0.10.21, BlazeFace short-range float16 v1. Saved console diagnostics include `INFO: Created TensorFlow Lite XNNPACK delegate for CPU.` The graph also uses WebGL for its image-processing path; CPU refers to the model inference delegate, not an assertion that all rendering/preprocessing avoids graphics APIs.
- Real photographic input: public-domain NASA/scikit-image photograph; tests crop and translate its actual pixels. The detector returned one face with center_x 0.146875 (confidence 0.8260986, 93.7 ms) and 0.8171875 (confidence 0.8064939, 125.5 ms) in the saved left/right run. These individual initial inference durations are diagnostics, not a representative throughput or latency benchmark.
- Detection boxes are produced by the real model. The worker, model, rectangle conversion, face mixer and skinned-eye renderer are never replaced by a fake box or fake face controller. Canvas screenshots show actual eye movement for left/right/up/down inputs. Camera preview is mirrored; uploaded image/video input is not.
- A recorded local WebM made from translated real photograph pixels passes through the visible file input, drives both sides and returns neutral at completion. A canvas MediaStream supplies pixels only at the external camera-device seam for automation. Neither is a physical live-camera session.
- Audio coexistence: real browser playback of a generated sine/silence WAV retains mouth, gaze and smile contributions. The saved speaking/pause screenshots were visually inspected: speaking mouth is open, and the pause returns to the configured smiling rest pose. At pause, jawOpen=0 and smile=0.5; that smile itself parts the lips. These frames must not be described as an independent physical audio/closed-lip synchronization measurement. The separate original 01 tests continue to verify ordinary no-smile silent-mouth behavior.
- Fresh-context photograph verification blocks external network requests and observed none. The detector runtime, WASM and model fetch locally. Missing local model, permission refusal and late permission grant cancellation have explicit public-page behavior; the model can be reloaded after failure.
- Full serial command: `node --test --test-concurrency=1 web/tests/public-page.test.cjs web/tests/gaze-public.test.cjs` => 18 tests, 18 pass, 0 fail, 68.3786782 seconds (01 original 11 + 08 new 7). JS syntax, whitespace and every staged source/model/fixture SHA-256 were checked. A prior run exposed a test-only five-second camera cold-start wait; it was aligned with the documented 15-second initialization deadline, then the full suite passed.
- Ignored generated evidence: `artifacts/ticket-08-{left,right,up,down,speaking,pause}.png`, `artifacts/ticket-08-detection.json`, `artifacts/ticket-08-fixed-face.webm`; the original 01 artifacts are also regenerated by its suite. These may be overwritten by future runs. Source fixture and local model/runtime are tracked with their original-byte hashes in `web/assets/vision/manifest.json`.

No physical camera permission/live-person movement, physical screen/speaker recording, 95%/200 ms audiovisual score, 30-minute/20-turn run, ASR/LLM/TTS integration, remote GPU inference or 5090 acceptance is claimed. No tracker/spec status was changed by this implementation. Source/license details and operation instructions are in [README-gaze.md](README-gaze.md).
